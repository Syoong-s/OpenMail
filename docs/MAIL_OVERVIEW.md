# 邮件概览与状态菜单

右侧没有打开邮件、对话或编辑器时显示邮件概览；打开正文时保留概览控件，关闭后恢复。继续尊重原有单栏/分栏设置和独立文件预览，不抢占正在阅读或编辑的页面。

## 界面与统计口径

- 顶部只显示日期，移除“邮件概览”和账户范围副标题。下方显示所选日期收到、发出的数量，以及近一年有邮件往来的天数。默认选择今天，跨午夜后自动推进仍停留在今天的视图。
- 53 周热力图从周一开始，按本机时区的邮件日期统计。悬停显示该日收发数量；点击日期或使用方向键可以切换时间线，右侧也提供前一天、后一天和今天按钮。
- 时间线按时间倒序排列，区分收到/发出，展示发件人或收件人、主题、摘要及时间。每行提供完成、已读、废纸篓按钮；完成使用实际归档，已读与归档原位更新，移入废纸篓后移除对应项。
- 统计使用已同步到本机且仍可用的邮件，受左侧账户筛选及自定义收件箱的账户范围约束，包含归档，排除草稿、垃圾邮件和废纸篓。删除缓存或调整同步保留范围也会改变统计；这不是服务器永久历史统计。
- 发送方向根据对应账户的发件地址或已发送文件夹判断。两个自有账户互发邮件分别计入其收、发记录。
- 相同账户、Message-ID、发件人、主题和时间的文件夹副本归为一项。缺少真实 Message-ID 的邮件按独立本地记录保留；不跨账户合并。已读动作处理该项的全部可用副本，移动针对当前显示的来源。一个副本已移入废纸篓/垃圾邮件时，不让尚待同步的所有邮件副本重新出现在概览。

页面使用原生 GTK 控件、Pango 字体及 Cairo 矢量绘图，适配深浅主题和窄阅读区，没有额外浏览器或图表依赖。时间线首次创建最多 60 项，可继续展开当天全部记录。空白日期展示真实空状态，不生成示例邮件。

## 性能与状态更新

日历在已有后台本地执行器的 `activity` 通道维护会话缓存。首次读取近一年的轻量元数据，之后切换日期、账户、分页或重新打开概览均复用缓存；不再每两秒查询邮件修订号或重复扫描整年。正文预览按需批量读取，最多缓存 512 项，不解析 MIME、不读取附件或原始邮件。

`activity_changes` 通过 SQLite 事务触发器合并发生变化的邮件 ID，记录新增、删除、收发信息、已读、归档、垃圾/废纸篓、远程缺失以及文件夹映射变化。事务提交后 `Store` 通知界面，后台只按这些 ID 更新缓存；回滚、无变化写入和界面偏好修改不会触发统计更新。同步、导入和本地动作共用此入口，不依赖各个按钮单独发通知。隐藏页面暂停渲染，下次打开再补齐变更。

变更记录保留最近 8192 个修订范围，同一 ID 合并存储。进程首次打开、缓存落后超过保留范围或系统日期倒退时才完整重建；正常跨午夜只移除过期日期并读取新一天。常规定时器仅比较内存中的日期，不查询邮件。缓存是会话级的，程序重启会重新从本地数据库建立，不访问远程邮箱。

行控件按本地邮件 ID 保留，已读/归档不重建整条时间线。操作继续使用本地提交与后台隐式同步，不为展示或点击额外访问真实 IMAP/SMTP。

更多菜单改为分组的双列图标按钮，保留原有命令控制器；分类与识别默认折叠。暂存、垃圾邮件、提醒、标签以底色和勾选标记表达当前状态。暂存和垃圾邮件名称保持简短，反向操作含义放在悬停提示中；点击已高亮的垃圾邮件按钮移回实际收件箱。永久删除继续使用原有确认流程。

## 配色

默认深色使用蓝灰层次，浅色使用暖白工作区和淡蓝灰侧栏。辅助色统一由 `semantic_style.py` 管理：青绿表示完成/收到，蓝色表示已读/信息，暖金表示置顶/提醒，淡紫表示发出/标签，柔和玫红表示删除/垃圾邮件。颜色集中在少量图标、细边、统计卡片和激活状态，正文保持清晰中性色。聚焦卡片、侧栏、设置、选择器、菜单、通知和编辑器使用同一套低饱和辅助色；用户保存的自定义基础色和邮件气泡颜色仍被保留。

## 运行与验证

本次不增加依赖、不编译原生库；目标仍是 Windows/Linux 桌面应用，不涉及 HPC。测试解释器为 WSL Python 3.14.4 和现有 Windows 包的 CPython 3.14.5，原生验证沿用 GTK 3.24、Pango、Cairo 和 WebView2。

从仓库目录执行：

```sh
./run.sh --demo
python3 -B tools/run_tests.py --output .runtime/palette-cache-tests
python3 -B tools/verify_mail_activity.py --output .runtime/palette-cache-native
```

原生验收需要完整图形运行库；Windows 下使用已有包内 Python 执行同一脚本，脚本按解释器位置发现运行库。完整测试可用 `--bundle` 指向已有包，并用 `--qa-openssl-dir` 指定 OpenSSL CLI 以隔离 TLS 测试配置。

`test_mail_activity.py` 覆盖账户隔离、重复文件夹副本、缺少 Message-ID、自有账户互发、本地日期边界、归档、垃圾与废纸篓排除、元数据查询和分页完整计数。`test_activity_cache.py` 用真实 SQL 跟踪验证日期/账户切换不重扫、增量结果与完整查询一致、提交/回滚事件、文件夹映射变更以及跨日/过期日志恢复。原生验收使用临时演示资料及合成邮件，禁止真实邮件收发，验证空闲时无概览请求，并输出深色、浅色、窄窗口、菜单、聚焦、侧栏和设置截图。

本地报告位于 `.runtime/palette-cache-tests/`、`.runtime/palette-cache-windows-tests/`、`.runtime/palette-cache-native/`，不属于发行产物。源码修改不会自动更新已安装的程序。

本次 Windows/Linux 完整测试各 380 项，零失败与错误，分别跳过 5/6 项平台测试。Windows 概览专项 11 项、聚焦/编辑器 6 项、侧栏/即时操作 7 项通过；辅助报告分别位于 `.runtime/palette-cache-composer/` 和 `.runtime/palette-cache-navigation/`。概览验收记录全年加载 1 次、连续三个邮件动作仅补丁更新 3 条记录，空闲期间没有概览请求。结果来自隔离的合成邮箱，不代表任意真实大邮箱的耗时。当前 WSL 缺少 WebKitGTK 4.1，Linux 富文本界面未作原生验收。
